# چک‌لیست تاچ و استفادهٔ واقعی (پوز، سالن، آشپزخانه)

این سند بند «UI تاچ‌فرست» از سند الزامات را می‌بندد. صادقانه: **هیچ اندازه‌گیری‌ای روی دستگاه
واقعی انجام نشده** — این محیط تبلت ندارد. آنچه انجام شده تعریف معیار و اصلاح کنترل‌هایی است که
از همان معیار رد می‌شدند.

## معیارها

| معیار | عدد | چرا |
|---|---|---|
| هدف لمس | ≥ ۴۴×۴۴ px (۱۱ Tailwind) | دست خیس/دستکش‌دار، بدون نگاه دقیق |
| فاصله دو کنترل مجاور | ≥ ۸ px | ضربهٔ سهوی روی «برگشت» کنار «تأیید» |
| متن روی UI | ≥ ۱۲ px، متن اصلی ≥ ۱۴ px | خواندن از فاصله یک متری |
| تغییر وضعیت یک‌ضربه‌ای | بدون دیالوگ تأیید | تأیید اضافه یعنی ضربه‌های بیشتر وسط سرویس |
| قابل استفاده در ۳۶۰ px عرض | بدون اسکرول افقی | موبایل گارسون |

## چه چیزی اصلاح شد

| صفحه | مشکل | اصلاح |
|---|---|---|
| تخته سالن | دکمه‌های وضعیت میز ۲۸ px (`h-7`) بودند | `h-9` + `px-2.5` + متن ۱۲ px |
| تنظیمات میز | دکمهٔ QR و حذف ۳۲ px | `size-10` (۴۰ px) — صندوق‌دار کنار میز ایستاده |
| آشپزخانه (KDS) | «مرحله بعد» اندازهٔ پیش‌فرض `sm` | `min-h-11 px-4`؛ سلکت وضعیت `h-11` |
| صندوق | کارت آیتم از قبل `min-h-20` بود | بدون تغییر (معیار را داشت) |

## چه چیزی هنوز اندازه‌گیری نشده

- زمان پاسخ تاچ → بازخورد بصری روی دستگاه واقعی.
- اسکرول افقی در ۳۶۰ px روی هر صفحه؛ فقط از روی کد قابل قضاوت است، نه اندازه‌گیری شده.
- کنتراست رنگ در نور روز (تراس).

مسیر گرفتن عدد: استقرار روی یک نسخه با دادهٔ واقعی، سپس Lighthouse (`npm run test:perf`) و
یک دور دستی با تبلت ۱۰ اینچ و موبایل ۳۶۰ px.
