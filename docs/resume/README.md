# Resume module (WebinoDashboard)

Generic, per-tenant LinkedIn-style resume. Every section is its own entity/table with CRUD; the page builder renders it with
`resume.*` widgets; themes are token sets + layout presets. ERP mirrors the same section slugs, fields and widget names.

## Data model
Canonical schema: `backend/resources/resume/schema.json` (frontend copy `frontend/modules/resume/lib/schema.json`), generated by
`scripts/resume/gen_schema.py` together with the migration and models. Change the script, regenerate, and add a **new** migration.

Common columns on list sections: `id, tenant_id, order, visibility (public|hidden|private_link), is_placeholder, created_at, updated_at`.
Single sections (identity, about, settings) have one row per tenant (no order/visibility).

- **ResumeDate** = `{g: "YYYY[-MM[-DD]]", j: "YYYY[-MM[-DD]]", precision: year|month|day}`. Send either calendar; the API fills the other (Jalali ⇄ Gregorian).
- Bilingual fields are `<key>_fa` / `<key>_en`; a required bilingual field needs at least one of them. Renderers fall back to the other language.
- Media fields hold media-library ids of the same tenant (validated). Public payload resolves them under `media`.
- `duration_months` is computed for range sections.

## API
Admin (auth: sanctum, `staff`, `module:resume` (= submodule `resume.profile` enabled), `can:content.manage`):

| method | path | notes |
|---|---|---|
| GET | `/api/v1/resume/schema` | schema.json |
| GET | `/api/v1/resume/overview` | count + placeholder count per section |
| GET | `/api/v1/resume/{section}` | list (ordered) or the single row |
| POST | `/api/v1/resume/{section}` | create list item (422 on validation) |
| PUT | `/api/v1/resume/{section}/{id}` | partial update |
| DELETE | `/api/v1/resume/{section}/{id}` | |
| POST | `/api/v1/resume/{section}/reorder` | `{ids:[…]}` full new order |
| PUT | `/api/v1/resume/{identity\|about\|settings}` | update single section |
| GET | `/api/v1/resume/themes` | theme catalog (tokens + layout) |
| POST | `/api/v1/resume/theme/apply` | `{theme_key, langs?:["fa","en"]}` → rewrites builder pages `home` (fa) + `en` (en, same translation_group → hreflang); old documents saved as BuilderRevision reason `resume-theme` |
| POST | `/api/v1/resume/import?replace=1` | body = data.json shape (throttled) |
| GET/PUT | `/api/v1/settings/site-language` | `{default_locale: fa\|en}` — generic, every site type (tenants.default_locale) |

Public (tenant by host, `public.module:profile`):
- `GET /api/v1/public/resume/full[?key=<private_token>]` — all sections (public rows; + `private_link` rows with the key), `settings`, `theme`, `media` map. Private fields (`birth_date`, `private_token`) are never exposed.
- `GET /api/v1/public/site-language`
- Legacy `GET /api/v1/public/resume` and `/api/v1/resume/profile` (old single-row profile) are unchanged.

## Import / seed
`php artisan resume:import <tenant id|slug|domain> <file.json> [--replace] [--theme=<key>] [--locale=fa|en]`
accepts the `resume-mockups/data.json` shape (`profile` → identity, `theme` → settings, skills matched by name for `skill_ids`)
and `*_path` keys (`avatar_path`, `cutout_path`, `cover_path`, `logo_path`, `gallery_paths`, `media_paths`) relative to the JSON file, stored into the media library.
Site content lives outside the generic code: `deploy/sites/<domain>/resume/` (see arsalanarghavan.ir).

## Languages
Pages: fa page = slug `home` (RTL, Jalali, Yekan Bakh), en page = slug `en` (LTR, Gregorian, Inter) in one translation group, so the existing SEO
builder emits hreflang alternates and per-page SEO. Widgets take `lang` = `auto` (page language) | `fa` | `en`.

## Themes
`backend/resources/resume/themes.json` (generated by `scripts/resume/gen_themes.py`, copy in frontend). Keys:
- `code-noir` — کد نوآر / Code Noir: Dark, terminal-inspired, for developers
- `atelier-editorial` — آتلیه ادیتوریال / Atelier Editorial: Magazine look on warm cream, for academics and consultants
- `aurora-glass` — شفق شیشه‌ای / Aurora Glass: Aurora gradients with glass cards, for creatives and startups
- `story` — داستان (Story) / Story: Full-page narrative: giant name over a portrait cut-out, parallax, chapters and case studies (full page)
- `webina-os` — وبینا OS / Webina OS: Full-page desktop OS: terminal, career git log, skills package.json, project launcher and ⌘K search (full page)

Tokens use the ERP shell names `--bg --surface --text --muted --border --accent --accent-fg` (+ `--accent-2`) with a light and dark pair;
`settings.mode=system` follows `prefers-color-scheme` / `.dark`. Accent: `settings.accent`/`accent_dark` → (full-page themes) the site accent from builder globals → theme default.
Switching theme only changes `settings.theme_key`; «اعمال چیدمان تم» rewrites the layout (with backup).
